# Knowledge context development hill climb

This is a synthetic development exercise with main-author expectations. It is not a calibrated human benchmark, production authentication audit, or an evaluation of actual photographs. Source-reading boundaries and the proposed live comparison are in [RFC 0011](../rfcs/0011-private-knowledge-context.md).

| Candidate/check | Observation | Bounded response |
| --- | --- | --- |
| Unchanged checked-out base, full suite | 173 passed; 8 timeouts in two orchestration test files | Both partially mocked the chat client but left real people prefetch active. Add the same prefetch boundary mock already used by the other orchestration suite. Dedicated prefetch tests remain real contract tests. |
| Test-first reference stub | 29 failures | Implement scope checks, pinned source integrity, required coverage, countervoice preservation, bounded output, and explicit dispositions. |
| First reference candidate | 29/29 passed | Add adversarial cases before changing the implementation. |
| Policy/correction replay and malformed scope probe | 29 passed; 2 failed | Unchanged text reused the old key after scope changes; a numeric prefix threw. Bind policy/source/coverage into a `knowledge-v2` identity and type-check the prefix. |
| Revised affected suite | 39/39 passed | Includes all 31 context tests and the 8 formerly timing-out orchestration tests. |
| Cross-machine CI receipt | CI included two runtime cache files that a local global ignore hid; new repository-ignore test failed (31 passed, 1 failed) | Ignore `/.cache/` in the repository and disable global excludes when fingerprinting. The focused suite now includes this portable cache-boundary check. |

The final receipt is generated by `npm run evals:knowledge` at `evals/reports/knowledge-context.json`. It fingerprints tracked and nonignored candidate files, excluding only that self-referential receipt, and checks for changes during the focused run. `npm run hillclimb` precedes it with the full regression suite. Commit identity is recorded by Git/CI; the content fingerprint also covers documentation, test expectations, and the evaluator itself.

No new TODOs are introduced. JSON-validity and retry-recovery rates for real LLM replies are unmeasured because this task makes no model requests. The hard gates are conjunctive; a useful-positive case must pass as well as every hold case. The malicious-text case proves that serialization preserves data as data and strips extra fields; it does not prove an LLM will resist that text. Live client authorization, corpus recall, graph traversal, provider retention, sink isolation, and editorial quality remain future acceptance work.
