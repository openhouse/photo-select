The final receipt is generated by `npm run evals:knowledge` at `evals/reports/knowledge-context.json`. It fingerprints tracked and nonignored candidate files, excluding only that self-referential receipt, and checks for changes during the focused run. `npm run hillclimb` precedes it with the full regression suite. Commit identity is recorded by Git/CI; the content fingerprint also covers documentation, test expectations, and the evaluator itself.

No new TODOs are introduced. JSON-validity and retry-recovery rates for real LLM replies are unmeasured because this task makes no model requests. The hard gates are conjunctive; a useful-positive case must pass as well as every hold case. The malicious-text case proves that serialization preserves data as data and strips extra fields; it does not prove an LLM will resist that text. Live client authorization, corpus recall, graph traversal, provider retention, sink isolation, and editorial quality remain future acceptance work.

### Eval-audit findings

**Error analysis — observed gap, corrected in the reference:** Existing packet tests did not exercise a live inquiry sequence. The added hand-authored traces expose reference-checker failures; they are not production traces or measured model errors.

**Pipeline hygiene — missing-suite risk, guarded:** Vitest can match one requested file while another is absent. The receipt runner now requires results for both named suites before writing a passing receipt. All final files, including this log and the new checker, enter the candidate fingerprint.

**Human review and labeled data — unmeasured:** No live retrieval/model traces or Jamie-labeled edits exist for this new mode. No judge is deployed or calibrated. Source recall, citation entailment, injection resistance, and usefulness require the private canary described in RFC 0012. Development case counts are not quality estimates.

The combined PR exceeds the AGENTS 300-line warning and 500-line flag thresholds. Change-set review flag: `--mechanical`. This flag records the required large-change marker; the RFC and evaluator logic require substantive review and are not claimed to be mechanical transformations. This revision changes no production source, prompts, dependencies, or application options. It grants no merge or live-access authority.
